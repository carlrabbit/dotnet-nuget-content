# M0006 — Semantic version increments and explicit consumer synchronization

## Purpose and compatibility

Provide convenient increment-based immutable packaging and safe, explicit update of local .NET project references to a verified content-package version. The product is for developers/project maintainers, **not an agent-specific tool**. Preserve all M0001–M0005 existing commands, defaults, public manifest v1, workspace marker v1 and legacy JSON contracts. Windows x64 Native AOT .NET tool only. Keep existing xUnit project infrastructure unchanged for this milestone; TUnit migration is deferred and not a product requirement.

## Version increment contract

Extend **managed** single-package `pack` and `workspace pack` with `--major`, `--minor`, `--patch`, exactly one of these or `--version VERSION` required. Do not change initial unmanaged package creation, which still requires `--version`. Resolve relative increments from the selected managed baseline version, never feed state, filenames, workspace pin guessing, or latest published version. For a stable normalized three-numeric-component version M.m.p, major -> (M+1).0.0, minor -> M.(m+1).0, patch -> M.m.(p+1). Use NuGet.Versioning parsing/normalization and reject non-stable/prerelease/build-metadata or non-three-part baselines for relative increments; explicit `--version` remains supported subject to existing strictly-increasing version rules. Reject conflicting switches, overflow, unchanged content, output collisions and invalid versions before publishing any final package. The resulting nuspec, filename, manifest and appended history must agree; managed workspace baseline and project-workspace pin remain unchanged. Root/help/README reflect the added switches.

## Explicit consumer synchronization contract

Add `workspace references update --alias NAME [--version VERSION] [--workspace ROOT] [--apply] [--json]` as a distinct operation. The default is **read-only preview**; `--apply` is the only write authorization. A missing version means the workspace member's **pinned version**. An explicit version is permitted only if a **locally available, valid managed package** for the same package ID and exact requested version can be identified unambiguously within registered workspace-local package files (or through an explicit `--package FILE` option; if implemented, verify content, ID/version and root boundary). Do not use feed resolution or restore. Never infer an unpinned newly packed version merely from its filename.

Only mutate explicitly supported local MSBuild package declarations found by bounded M0005 usage discovery: literal direct `PackageReference Version` attribute or child `Version`, and literal `PackageVersion` attributes/child nodes in `Directory.Packages.props` for central version management. For projects using a central declaration, update the effective central declaration **once**, not each consuming project; central-version-only declarations unrelated to a selected real consumer must not be modified. Preserve unrelated projects/packages, relevant XML structure, indentation and encoding as far as feasible; avoid wholesale XML reformatting. Detect and reject ambiguity: duplicated/conflicting declarations, conditions whose effective target cannot be determined, dynamic properties/imported versions, unsupported version syntax, malformed files, or sources outside selected project root. `PackageReference Update` is a potential declaration but update it only when its meaning is unambiguous; otherwise report it as unsupported.

Preview outputs structured proposal: target package ID/version, current declarations and their paths/old/new values, supported/no-op/unresolved classification, and any blocking diagnostics. Apply must use the **same computed plan**, recheck file state (content fingerprint) before writing, then write via staged files; no unsupported/malformed target may cause a partial intentional update. Handle file-write exceptions with rollback of already committed files where possible; record partial/recovery information if rollback fails. No blanket claim of crash-atomic cross-file edits: abrupt termination may interrupt multi-file replacement, so release evidence must distinguish preflight/handled failure from forced termination. `--json` has a separately documented versioned output schema, with stable field names/order, one stdout object, stderr diagnostics and existing CLI exit-code conventions; do not mutate M0003/M0005 schemas. The preview must not write generated NuGet files, project sources, workspace root marker, or cached data.

After reference updates, consumers must be able to restore from an explicitly configured isolated local NuGet source; this command must not perform restore, modify NuGet.Config, publish packages, change workspace pins, or alter other content members. Consumer updates are independent of `pack` and `workspace set`; there is no implicit upgrade.

## Validation specialization

Existing Windows x64 .NET 11 SDK, Native AOT prerequisites, current **xUnit** test runner and PowerShell installed-tool validator. Local tests use real temp files, actual .nupkg packages and fixture .NET projects; full installed-tool acceptance uses exact built NuGet tool artifacts and real offline restore/build/copy-to-output byte check. Never install new test infrastructure, CI or host tooling. No scale/100-project performance gate in M0006: defer to 2.0 qualification.

## Reference update result JSON v1

`workspace references update --alias NAME [--version VERSION] [--workspace ROOT] [--apply] [--json]` emits one compact JSON object and newline. Without `--apply`, it is a read-only preview. `targetVersion` is the pinned workspace version unless a locally verified exact package version is supplied. `changes` are ordered by root-relative `/` path then source kind and contain literal old/new values. `classification` is `supported` or `noOp`. `blockers` are ordered by path then code; any blocker makes `canApply` false and prevents writes. Apply sets `applied:true` only after every staged file has been committed. A handled write failure reports `partialState` with rollback outcome. Errors outside a plan use stderr and existing exit codes. The public schema is `M0006-reference-update.schema.json`; M0003/M0005 JSON v1 schemas are unchanged.

Only literal direct `PackageReference` `Version` attributes/children and effective local `Directory.Packages.props` `PackageVersion` declarations are eligible. Central declarations are changed only when a discovered project consumes them, once per central file. Preview does not write. Apply recomputes the same plan, fingerprints every source, stages edits beside source files, rechecks all fingerprints before replacement, and attempts to restore already-replaced files after a handled failure. MSBuild imports, conditions, dynamic values, duplicate declarations and malformed project XML block the complete write plan. Cross-file edits are not crash-atomic. The command does not restore, edit feeds/configuration, update workspace pins, or infer newly packed versions from filenames.
