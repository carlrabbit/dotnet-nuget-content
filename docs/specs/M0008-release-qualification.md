# M0008 — 2.0.0 release qualification contract

## Target and release boundary
Qualify, but **do not publish**, the Windows x64 Native AOT NuGet .NET tool `dotnet-nuget-content` version **2.0.0** and matching `dotnet-nuget-content.win-x64` **2.0.0**. All other distribution targets remain unsupported. Developer-facing CLI; the agentic guide governs implementation, not user interface.

## Candidate provenance and staging
Use the existing human-operated `eng/publish.ps1` preparation and publication architecture; update its hard-coded 1.0.0 assumptions, dependencies, metadata, help, operator docs, and validation scripts for 2.0.0. `-Prepare` remains safe offline/local and never performs a public push. `-TestPublish` must simulate push/failure without public network or credentials. `-Publish` requires exact NuGet.org target, explicit human confirmation, already-qualified unmodified bytes, correct both package identities/hashes, and RID package first; it is never invoked during this milestone. Candidate `candidate.json`/receipts must be self-contained, versioned where a persisted contract needs it, and tied to source SHA, SDK and command invocation. A developer PR's pre-merge candidate is preliminary. **Authoritative release candidate must be rebuilt and fully qualified from clean final intended merged commit**, with publication kept strictly outside the milestone. No source changes after certification without full fresh qualification.

## Compatibility
Preserve v1 content manifest, root workspace marker and existing M0003/M0005/M0006/M0007 JSON schemas and behavior. No silent migrations or 2.0 format bump. Version 2.0.0 refers to the **tool**, not package versions created by users. All M0001–M0007 commands remain supported. Preserve preview-first reference updates, explicit pin updates, immutable snapshots, and intentionally non-crash-atomic multi-file changes/cleanup. Fix only demonstrated release blockers; material public contract changes require planning escalation.

## Scale qualification, not optimization project
Use reproducible synthetic project root of **100 real SDK-style projects, 10 registered content package IDs**, mixed direct and central PackageReference declaration types, some absent/dynamic/conditional values, independent managed directories and generated-file exclusions. Exercise `workspace usage`, `workspace inspect`, `workspace references update` preview and apply for one selected package, ensuring unrelated files unchanged, negative cases fail closed, and bounded discovery results. Record fixture seed/inputs, invocation, project/reference counts, environment, elapsed wall time and peak process memory for each operation and total, and actual outputs. Repeat run or stable sampling enough to identify flaky/unbounded behavior. **No arbitrary speed threshold** or new benchmark infrastructure: acceptance is correct bounded completion without resource explosion/hangs on authorized machine; surprising performance is documented and escalated if significant. Performance tuning only to remove a demonstrated blocker.

## Safety qualification
Exercise benign and negative cases with actual .nupkg and Windows filesystem: overlapping roots, path traversal, junction/reparse paths, content hashes, modified and clean old snapshots, no-clobber, atomic package/pin commit and controlled interruption after observing stage start. Report exact partial filesystem state for interrupted recursive delete; do not imply rollback. No hostile ZIP-bomb defense expansion. Existing xUnit tests retained during M0008; migration to TUnit deferred.

## Installed and release validation
Use authorized Windows 11 x64 .NET 11 SDK and installed Native AOT prerequisites; existing PowerShell validators and operator release entrypoint. Validate both top-level pointer and RID artifact metadata and actual installed executable. Isolate local feed and NuGet caches when appropriate; restore/build independent .NET consumer from the candidate's generated content package and verify binary copy-to-output oracle. Include local tool-manifest and tool-path install, update/uninstall, nonzero/error conventions. No host provisioning, CI workflow changes, public publication, other-RID fallback, standalone executable distribution, or network-based product functionality.

## Docs and closure
Update package metadata from old 1.0 text, `README.md`, `docs/nuget/README.md`, `docs/release/HELP-TEXT.md`, `docs/release/PACKAGE-METADATA.md`, `docs/release/PUBLISHING.md`, `docs/MILESTONES.md` and relevant spec references. Correct M0007 milestone index state to `done` only after confirming merged PR. Release report and checklist must distinguish implementation branch validation from final-merged-source qualification and explicit human approval. If candidate cannot be built on final merge commit within execution timing, leave that gate pending: no premature release-qualified claim.
